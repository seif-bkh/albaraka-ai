# 08 — API Design

**API-first**: [`specs/openapi.yaml`](../specs/openapi.yaml) is the source of truth. TypeScript types
and the Angular API client are generated from it (`libs/shared-contracts`), as are the Spring
controller interfaces (`@OpenAPIDefinition` + `springdoc-openapi` for verification). A breaking
change detected by `oasdiff` in CI fails the build unless the version prefix is bumped.

## 1. Principles

| Principle | Application |
|---|---|
| Resource-oriented REST, plural nouns | `/admin/documents`, `/admin/reviews` |
| Version in the path | `/api/v1/...`; a breaking change ⇒ `/api/v2` (both served during deprecation) |
| Two facades, one API surface | `/api/v1/**` = frontoffice/public, `/api/v1/admin/**` = backoffice (separate CORS policy, separate rate limits, separate WAF rules) |
| Errors as RFC 9457 | `application/problem+json` with a stable `type` URI, a bank `code`, and trilingual `title` |
| Idempotency where it matters | `Idempotency-Key` header on every mutating POST |
| Optimistic concurrency | `ETag` / `If-Match` on versioned resources (`document_version`, `prompt_version`, `retrieval_config`) |
| Cursor pagination for feeds, page pagination for admin tables | `?cursor=&limit=` / `?page=&size=&sort=` |
| Locale is explicit | `Accept-Language` on every call; response bodies carry `locale` where text is localised |
| No personal data in URLs | identifiers are UUIDv7 only |
| Traceability | every response carries `X-Correlation-Id` (echoed if provided) |

## 2. Conventions

### 2.1 Headers

| Direction | Header | Notes |
|---|---|---|
| Request | `Authorization: Bearer <jwt>` | absent for anonymous frontoffice use |
| Request | `Accept-Language: fr-FR \| ar-TN \| en-GB` | drives localised labels and error titles |
| Request | `X-Correlation-Id` | UUID; generated by the client, propagated to traces and logs |
| Request | `Idempotency-Key` | required on `POST /assistant/conversations/*/messages`, `POST /admin/documents`, `POST /admin/reviews/*/decision` |
| Request | `If-Match` | required on `PUT/PATCH` of versioned resources |
| Response | `X-Correlation-Id`, `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` | |
| Response | `Deprecation`, `Sunset`, `Link: rel="successor-version"` | during deprecation windows |
| Response (SSE) | `Content-Type: text/event-stream`, `Cache-Control: no-store`, `X-Accel-Buffering: no` | nginx buffering disabled |

### 2.2 Error model

```json
{
  "type": "https://api.albaraka.com.tn/errors/retrieval/no-approved-content",
  "title": "Aucun contenu approuvé ne permet de répondre",
  "title_ar": "لا يوجد محتوى معتمد يسمح بالإجابة",
  "title_en": "No approved content available to answer",
  "status": 422,
  "code": "RAG.NO_APPROVED_CONTENT",
  "detail": "intent=TARIFF_FEES, collection=TARIFFS, best_score=0.21 < 0.35",
  "instance": "/api/v1/assistant/conversations/0198…/messages",
  "correlationId": "0b1c…",
  "refusalCode": "REF-05"
}
```

| `code` prefix | HTTP | Meaning |
|---|---|---|
| `VALIDATION.*` | 400 | Bean-validation failure (field errors in `errors[]`) |
| `AUTH.UNAUTHENTICATED` / `AUTH.FORBIDDEN` | 401 / 403 | JWT missing/invalid, or insufficient authority |
| `AUTH.MFA_REQUIRED` | 403 | step-up needed for a sensitive admin action |
| `RESOURCE.NOT_FOUND` / `RESOURCE.CONFLICT` | 404 / 409 | incl. ETag mismatch (`CONFLICT.STALE_VERSION`) |
| `GOVERNANCE.SELF_APPROVAL` | 422 | two-eyes violation |
| `GOVERNANCE.QUORUM_NOT_MET` | 422 | T3 approval incomplete |
| `GOVERNANCE.STATE_TRANSITION_INVALID` | 422 | lifecycle violation |
| `RAG.NO_APPROVED_CONTENT` | 422 | honest-ignorance path (not an error for the user — surfaced as REF-05) |
| `GUARDRAIL.BLOCKED_INPUT` / `GUARDRAIL.BLOCKED_OUTPUT` | 422 | policy block, carries `refusalCode` |
| `PROVIDER.UNAVAILABLE` / `PROVIDER.RATE_LIMITED` / `PROVIDER.BUDGET_EXHAUSTED` | 503 / 429 / 503 | degradation ladder engaged |
| `INGESTION.UNSUPPORTED_FORMAT` / `INGESTION.SCAN_INFECTED` | 415 / 422 | upload rejected |
| `RATE_LIMIT.EXCEEDED` | 429 | with `Retry-After` |
| `INTERNAL.*` | 500 | correlation id only, no internals leaked |

### 2.3 Pagination & filtering (admin)

```
GET /api/v1/admin/documents?collection=PRODUCTS_RETAIL&state=PUBLISHED&product=MOURABAHA
    &q=mourabaha&lang=fr-FR&page=0&size=25&sort=updatedAt,desc
→ 200 { "content": [...], "page": {"number":0,"size":25,"totalElements":137,"totalPages":6} }
```
Filters are whitelisted per endpoint (no generic property traversal → no injection/enumeration risk).

## 3. Frontoffice API (`/api/v1`)

| POST | `/assistant/messages/{id}/feedback` | anon/customer | Rating + reason code + free text + contact opt-in |
| GET | `/assistant/messages/{id}/sources` | anon/customer | Full citation detail (title, url, validity, collection) |

| POST | `/assistant/fatwa-requests` | anon/customer | Submit a question for the Sharia committee → `{ref, state, slaDueAt}` |

| GET | `/public/documents/{id}` | anon | Read a published document (rendered, with validity dates) |
| GET | `/public/agencies?locale=&region=` | anon | Branch/agency locator data |

### 3.1 SSE streaming contract

`POST /assistant/conversations/{id}/messages` returns `text/event-stream`:

```
event: accepted
data: {"messageId":"0198f…","conversationId":"0198e…","locale":"ar-TN","dir":"rtl"}

event: status
data: {"stage":"RETRIEVING","label_ar":"أبحث في الوثائق المعتمدة…"}

event: sources
data: {"citations":[{"id":"S1","chunkId":"…","documentTitle":"Mourabaha — particuliers",
        "locale":"fr-FR","url":"/public/documents/…#S1","validUntil":"2026-12-31","score":0.83}]}

event: token
data: {"delta":"المرابحة هي "}

event: token
data: {"delta":"عملية تمويل…"}

event: answer
data: {"messageId":"0198f…","answerMarkdown":"…","language":"ar-TN","confidence":0.81,
       "usedSources":["S1","S4"],"caveats":[],"needsHuman":false,
       "disclaimers":["DISC-GENERAL","DISC-ELIGIBILITY"],
       "models":{"chat":"llama-3.3-70b-versatile","degradationStep":1},
       "latencyMs":2410,"ttftMs":690}

event: done
data: {"messageId":"0198f…","tokensIn":7021,"tokensOut":418}
```

Alternative terminal events instead of `answer`:

```
event: refusal
data: {"refusalCode":"REF-03","titleAr":"…","titleFr":"…","titleEn":"…",
       "fatwaRequestRef":"FR-2026-00123","sources":[]}

event: error
data: {"code":"PROVIDER.RATE_LIMITED","retryAfterMs":4000,"degradationStep":2}
```

Rules: `sources` is always emitted **before** the first `token` (the UI renders the citation rail
first); exactly one terminal event (`answer` | `refusal` | `error`) then `done`; the client must treat
an unterminated stream as `error` after a 30 s idle timeout; `Last-Event-ID` resume is **not**
supported in v1 (a reconnect re-issues the request with the same `Idempotency-Key`, which returns the
persisted answer instead of regenerating).

### 5.3 Approve content (two-eyes enforced)

```bash
POST /api/v1/admin/reviews/01990…/tasks/01991…/decision
-H 'If-Match: "3"' -H 'Idempotency-Key: 9a2…'
{ "decision": "APPROVE", "reasonFr": "Conforme à la fiche produit validée par le comité.",
  "reasonAr": "مطابق لبطاقة المنتج المعتمدة من اللجنة.",
  "reasonEn": "Matches the committee-approved product sheet.",
  "scope": "ALL_CHUNKS", "chunkIds": [] }
```
→ `422 GOVERNANCE.SELF_APPROVAL` if the caller submitted it; → `200` with the new review state, and
if all required decisions are present the document moves to `SHARIA_APPROVED` (publish is a separate,
also-approved action).

## 6. Internal events (AsyncAPI)

[`specs/asyncapi.yaml`](../specs/asyncapi.yaml) documents the in-process event bus (Spring
`ApplicationEventPublisher`, outbox-backed so events survive a crash):

| Event | Emitted when | Consumers |
|---|---|---|
| `document.version.submitted` | review requested | governance, notifications |
| `review.decided` | a decision is recorded | knowledge (state), audit, notifications |
| `content.published` | chunks became searchable | cache invalidation (`kb_epoch++`), analytics, eval scheduling |
| `content.withdrawn` | emergency removal | cache flush, incident, notifications |
| `guardrail.blocked` | any BLOCK decision | analytics, alerting, QA queue |
| `feedback.received` | customer rating | QA queue, `SHARIA_CONCERN` → review task |
| `fatwa.request.opened` | REF-03 issued | committee queue, SLA clock |
| `prompt.activated` / `model.activated` / `config.activated` | any runtime change | eval gate, cache flush, audit |
| `eval.completed` | an eval run finished | release pipeline (gate), notifications |
| `budget.threshold.crossed` | 80 % / 100 % of daily budget | degradation, alerting |

## 7. Rate limits

| Scope | Limit | On exceed |
|---|---|---|
| Anonymous widget, per IP | 6 messages/min, 40/hour, 3 conversations/day | `429` + captcha challenge |
| Authenticated customer | 12 messages/min, 300/day | `429` |
| Agent desk | 30 messages/min | `429` |
| Admin UI | 300 req/min per user | `429` |
| Ingestion uploads | 20 files/hour per user, 10 MB each, 500 MB/day | `429` / `413` |
| Provider budget | `model_config.daily_budget_usd` | degradation ladder, then `503 PROVIDER.BUDGET_EXHAUSTED` |

## 8. Compatibility & deprecation policy

1. **Additive** changes (new optional field, new endpoint, new enum value) ship without a version bump;
   clients must ignore unknown fields (enforced by generated clients).
2. **Breaking** changes (removed/renamed field, type change, new required field, removed endpoint,
   changed semantics) require `/api/v2` **or** a parallel field with a deprecation window ≥ 90 days.
3. Deprecation is signalled with `Deprecation` + `Sunset` headers and announced in `CHANGELOG.md`.
4. `oasdiff breaking main..HEAD` runs in CI; a finding fails the build unless labelled
   `api-breaking-approved` by two reviewers.
5. Enum values are **open** on the client side: generated TS types use string unions with a
   `| (string & {})` escape so a new server value never breaks an old deployed bundle.
